# Stardunk ARM64

Run **Stardunk 2.3.9** (Godzilab / Playdigious) on modern 64-bit-only Android phones.

Stardunk ships its game engine as a 32-bit ARM library (`armeabi-v7a`). Recent phones, such as the Pixel 10 series, no longer support 32-bit ARM code, so the game fails to start on them. This project builds a 64-bit replacement `libGame.so` that runs the original 32-bit engine through the [Dynarmic](https://github.com/lioncash/dynarmic) ARM32→ARM64 recompiler. The game's own Java code runs unmodified apart from two small fixes.

> **This repository contains no game code or assets.** You need your own copy of the Stardunk 2.3.9 APK. The build pulls the original engine out of that APK and repackages it on your machine.

## How it works

- **ELF loader:** the loader maps the original `libGame.so` into a 4 GiB guest address window. It applies the ARM relocations and runs the library's constructors and `JNI_OnLoad`.
- **CPU:** every Android thread that calls into the game gets its own Dynarmic instance. Nested JNI re-entry gets an extra instance per level. All instances share one exclusive monitor, so the game's locks and atomics work across threads.
- **HLE layer:** the library's ~190 imports are reimplemented on the host. That covers bionic libc, libm (softfp), pthreads, stdio, mmap and OpenGL ES 2.0. Guest pointers are translated as they cross the boundary, and the guest heap is a dlmalloc mspace.
- **JNI:** the game sees a complete JNIEnv/JavaVM (233 + 8 functions) that forwards to the real JVM. Object references, method IDs and field IDs become 32-bit handles. Varargs, `va_list` and `jvalue[]` calls are decoded from each method's signature.
- **Exports:** the 42 `Java_com_gzl_stardunk_glue_*` natives are exported with their real JNI signatures, so the original Java classes bind to the new library unchanged.
- **Java fixes** (`scripts/patch_java.py`):
  - The game used to re-request location forever if it was denied. It now asks once and continues either way.
  - Reading the last known location no longer crashes when permission is denied.

## Building

You need Linux x86-64 with `git`, `cmake` (3.20+), `curl`, `unzip`, `python3` and a JDK (17+).

```sh
scripts/setup.sh                  # one time: NDK r26d, build-tools, Boost, Dynarmic, apktool (~2 GB)
./build.sh /path/to/Stardunk_2.3.9.apk
adb install out/Stardunk-arm64.apk
```

`setup.sh` puts everything in `deps/`. To reuse copies you already have, set `ANDROID_NDK_HOME`, `BUILD_TOOLS`, `BOOST_ROOT`, `DYNARMIC_ROOT` or `APKTOOL_JAR`.

`build.sh` checks that the APK's engine matches version 2.3.9 (by SHA-256) and refuses to build anything else. The output APK is signed with a local debug key generated by `setup.sh`. If you have another build of the game installed, uninstall it first.

For debugging, `BRIDGE_TRACE=1 ./build.sh ...` logs every guest import call. Watch logcat for the `StardunkBridge` and `StardunkGuest` tags.

## Status

Tested on a Pixel 10a (Android 16, Mali-G715). The game reaches gameplay, rendering and touch input work, and profiles save. The menus, shop and online features haven't been tested thoroughly. Please file an issue with a logcat if something breaks.
